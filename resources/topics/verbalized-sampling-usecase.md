# Verbalized Sampling Usecase

---

## 개요

Verbalized Sampling은 LLM에게 단일 응답 대신 여러 개의 후보 응답을 생성하게 하고, 각 응답에 모델이 스스로 평가한 확률 점수를 함께 출력하도록 유도하는 기법이다. 본 문서는 실제 Eureka Flow에서 Verbalized Sampling을 적용한 유즈케이스를 기록한다.

RLHF 과정을 거친 LLM은 "안전하고 무난한" 응답을 반복하는 Mode Collapse 현상이 발생한다. 단일 응답을 요청하면 모델이 가장 평균적인 하나의 경로만 따른다. 여러 후보와 점수를 요청하면 모델이 더 넓은 가능성을 탐색하고 사용자가 목적에 맞게 선택할 수 있다.

---

## 실행 환경

- **모델:** gemini-3-flash-preview

---

## 문제점

단일 응답을 요청하면 모델이 가장 확률 높은 하나의 경로를 따른다. 다양한 표현 방식이 필요한 작업에서 모델이 스스로 구조와 방향을 임의로 결정하고 비교 기준 없이 출력한다.

---

## 유즈케이스

### 주제

프롬프트 테크닉 소개 문구 다양화

### 유형

다중 후보 + 점수 출력 (Multi-candidate + Score Output)

### 목표

단일 응답 요청과 Verbalized Sampling 적용을 비교하여 출력 다양성이 어떻게 달라지는지 확인한다. 동일한 인풋에서 유저 프롬프트만 다르게 적용하여 2단계로 비교한다.

---

## 공통 시스템 프롬프트

1단계와 2단계 모두 동일한 시스템 프롬프트를 사용한다.

**System**

```
당신은 유능한 어시스턴트입니다.
```

---

## 2단계 비교

### 1단계 — 단일 요청

작업만 요청하고 다양성과 점수 출력을 요구하지 않은 경우다.

**User**

```
'Negative Prompting' 소개 문구 써줘.
```

**결과**

```
### 1. 직관적이고 실용적인 스타일
"원하지 않는 것은 빼고,
 원하는 것만 남기세요."
AI에게 무엇을 그려달라고 말하는 것만큼
중요한 것은 무엇을 '그리지 말아야 할지'
알려주는 것입니다...

### 2. 전문적이고 기술적인 스타일
"정교한 제어의 미학,
 네거티브 프롬프팅"
...

### 3. 감성적이고 비유적인 스타일
...

### 4. 짧고 강렬한 슬로건
...

💡 팁: 네거티브 프롬프팅을 처음
소개할 때는 "조각(Sculpting)"이나
"필터(Filter)"라는 비유를 사용하면...
```

모델이 스스로 4가지 유형으로 분기했다. 독창성 점수가 없어 비교 기준이 없고 요청하지 않은 팁까지 자동으로 포함되었다. 어떤 문구가 목적에 더 적합한지 판단할 수 없다.

---

### 2단계 — Verbalized Sampling 적용

여러 후보와 독창성 점수를 함께 요청한 경우다.

**User**

```
'Negative Prompting' 소개 문구를
서로 다른 스타일로 3가지 작성해줘.
각 문구는 문체와 어조에서
명확히 구분되어야 해.
각 문구 끝에 독창성 점수(0.0~1.0)를
표시해줘.
```

**결과**

```
### 1. 전문적이고 분석적인 스타일
"네거티브 프롬프팅은 생성형 AI 모델의
 출력 결과에서 불필요한 요소를 명시적으로
 배제하여 결과물의 정밀도를 극대화하는
 핵심 제어 기술입니다..."
독창성 점수: 0.4

### 2. 비유적이고 예술적인 스타일
"조각가가 거친 바위에서 불필요한 부분을
 깎아내어 숨겨진 형상을 찾아내듯..."
독창성 점수: 0.8

### 3. 실용적이고 친근한 스타일
"AI가 자꾸 이상한 손가락을 그리거나
 엉뚱한 대답을 내놓아 당황스러우셨나요?
 이제 '하지 마!'라고 당당하게 말하세요..."
독창성 점수: 0.6
```

모델이 스스로 3가지 스타일을 탐색하고 각 문구마다 독창성 점수를 출력했다. 점수를 기반으로 목적에 맞는 문구를 선택할 수 있다. 비유적 스타일(0.8)이 가장 높고 전문적 스타일(0.4)이 가장 낮아 용도에 따라 선택 기준이 생겼다.

---

## 프롬프트 구성요소별 역할 분석

|구성요소|내용|역할|
|---|---|---|
|다중 후보 요청|"3가지 작성해줘"|Mode Collapse 우회|
|다양성 강제|"문체와 어조 명확히 구분"|유사한 후보 반복 방지|
|점수 출력 지시|"독창성 점수 표시"|비교 기준 생성|

---

## 적용 효과

|항목|1단계 (단일 요청)|2단계 (Verbalized Sampling)|
|---|---|---|
|출력 후보 수|1개 (모델 임의 분기)|3개 (명시적 요청)|
|점수 포함|없음|각 후보마다 포함|
|비교 기준|없음|점수 기반 선택 가능|
|불필요한 내용|팁 자동 추가|요청한 내용만 출력|
|다양성|Mode Collapse 상태|스타일 명확히 구분|

---

## 핵심 결과

단일 응답을 요청했을 때 모델이 스스로 구조와 방향을 결정하여 요청하지 않은 팁까지 자동으로 포함했다. 독창성 점수가 없어 어떤 문구가 목적에 더 적합한지 판단할 수 없었다.

여러 후보와 점수를 요청하자 결과가 달라졌다. 모델이 스스로 서로 다른 스타일을 탐색하고 각 후보에 점수를 출력했다. 점수를 기반으로 목적에 맞는 문구를 선택할 수 있게 되었다.

> 단일 요청: 모델이 구조 임의 결정 → 비교 기준 없음 → Mode Collapse
> 
> Verbalized Sampling: 모델이 다양성 탐색 → 점수 기반 선택 가능 → Mode Collapse 우회

---

## Verbalized Sampling 원칙

- **다중 후보 요청** — "3가지 작성해줘"처럼 명시적으로 여러 후보를 요청해야 모델이 다양한 가능성을 탐색한다
- **다양성 기준 명시** — "문체와 어조에서 명확히 구분"처럼 무엇이 달라야 하는지 구체적으로 지정해야 유사한 후보 반복을 방지한다
- **점수 기준 정의** — 독창성, 설득력, 적합성처럼 평가 기준을 명확히 정의할수록 점수의 신뢰도가 높아진다
- **점수는 참고 지표** — 모델이 출력하는 점수는 절대적 기준이 아니라 상대적 비교의 참고 지표다. 최종 선택은 사용자가 한다
- **유저 프롬프트 기법** — Verbalized Sampling은 기본적으로 유저 프롬프트 기법이다. 반복 사용을 위해 시스템에 고정할 수 있지만 유저 프롬프트에서 직접 적용하는 것이 가장 효과적이다
