
# Few-Shot Prompting Usecase

---

## 개요

Few-Shot Prompting은 LLM에 입력-출력 예시를 제공하여 모델이 패턴을 파악하고 새로운 입력에 동일하게 적용하도록 유도하는 기법이다. 본 문서는 실제 Eureka Flow에서 Few-Shot Prompting을 적용한 유즈케이스를 기록한다.

예시 없이 작업 지시만 제공하면 모델이 형식, 톤, 길이를 스스로 판단한다. 입력-출력 예시를 제공하면 모델이 패턴을 파악하여 일관된 형식의 출력을 생성한다.

## 문제점

작업 지시만으로는 모델이 원하는 형식과 톤을 정확히 파악하지 못한다. 별도의 예시가 없으면 모델이 형식, 길이, 톤을 스스로 판단하여 의도와 다른 결과가 나올 수 있다.

**기본 실행 결과**

```
**Few-Shot Prompting(퓨샷 프롬프팅)**에 대한 소개 문구를 용도에 맞춰 세 가지 버전으로 작성해 드립니다.

### 1. 핵심 요약형 (가이드북, 툴팁용)
> **"백 마디 설명보다 강력한 몇 개의 예시"**
...
### 2. 상세 설명형 (교육 자료, 블로그 포스팅용)
...
### 3. 비즈니스/실무 활용형 (업무 효율화 강조)
...
**💡 작성 팁:**
...
```

**문제점 정리**

첫째, 요청하지 않은 여러 컨셉으로 분기된다. 하나의 문구를 요청했는데 3가지 컨셉으로 나누어 출력한다.

둘째, 형식이 제각각이다. 메인 문구, 설명처럼 요청하지 않은 구조가 자동으로 생성된다.

셋째, 팁 등 불필요한 내용이 추가된다. 소개 문구만 요청했는데 작성 팁까지 자동으로 생성된다.

---

## 유즈케이스

### 주제

소개 문구 작성

### 유형

형식 일관성 (Format Consistency)

### 목표

예시 없이 작업 지시만 했을 때와 입력-출력 예시를 제공했을 때 출력이 어떻게 달라지는지 확인한다.
동일한 인풋에서 시스템 프롬프트만 다르게 적용하여 Few-Shot Prompting의 효과를 2단계로 비교한다.

---

## 공통 인풋

1단계와 2단계 모두 동일한 유저 인풋을 사용한다.

**User**

```
아래 프롬프트 테크닉의 소개 문구를 작성해주세요.

테크닉: Few-Shot Prompting
```

---

## 2단계 비교

### 1단계 — Zero-Shot (예시 없음)

작업 지시만 제공한 경우다. 예시가 없어 모델이 형식, 톤, 길이를 스스로 판단한다.

**System**

```
당신은 유능한 어시스턴트입니다.
```

**결과**

```
**Few-Shot Prompting(퓨샷 프롬프팅)**에 대한 소개 문구를 용도에 맞춰 세 가지 버전으로 작성해 드립니다.

---

### 1. 핵심 요약형 (가이드북, 툴팁용)
> **"백 마디 설명보다 강력한 몇 개의 예시"**
>
> Few-Shot Prompting은 모델에게 작업 수행 방식에 대한 **몇 가지 예시(Shot)**를 제공하여, 원하는 결과물의 형식과 스타일을 정확히 학습시키는 기법입니다. 복잡한 규칙을 일일이 설명하지 않아도 예시를 통해 AI가 문맥을 빠르게 파악하도록 돕습니다.

### 2. 상세 설명형 (교육 자료, 블로그 포스팅용)
> **"AI의 잠재력을 깨우는 예시의 힘, Few-Shot Prompting"**
>
> AI 모델이 질문의 의도를 완벽히 이해하지 못할 때, 가장 효과적인 해결책은 바로 '예시'를 보여주는 것입니다. Few-Shot Prompting은 프롬프트 내에 **[입력 - 출력]의 쌍**을 2~5개 정도 포함시켜 모델이 패턴을 인식하게 만듭니다. 이를 통해 일관된 톤앤매너 유지, 특수한 데이터 형식 출력, 복잡한 논리 구조 해결 등 제로샷(Zero-shot) 방식으로는 한계가 있는 작업에서 압도적인 성능 향상을 이끌어냅니다.

### 3. 비즈니스/실무 활용형 (업무 효율화 강조)
> **"정교한 결과물을 위한 필수 테크닉: Few-Shot Prompting"**
>
> 단순한 질문만으로는 부족한 비즈니스 환경에서 Few-Shot Prompting은 AI 답변의 정확도를 극대화합니다. 사용자가 원하는 특정 양식이나 전문 용어 활용법을 예시로 미리 보여줌으로써, 수정 보완에 드는 리소스를 획기적으로 줄여줍니다. AI를 단순한 챗봇을 넘어 나만의 전문 비서로 최적화하고 싶다면 반드시 마스터해야 할 프롬프트 전략입니다.

---

**💡 작성 팁:**
*   **Zero-Shot:** 예시 없이 바로 명령 (예: "이 문장을 번역해줘.")
*   **Few-Shot:** 예시를 주고 명령 (예: "A -> 가, B -> 나, C -> ?")
이 차이점을 강조하면 사용자가 기법의 필요성을 더 쉽게 이해할 수 있습니다.
```

요청하지 않은 3가지 컨셉으로 분기되었고 메인 문구, 설명처럼 불필요한 구조가 자동으로 생성되었다. 소개 문구만 원했는데 작성 팁까지 포함되었다.

---

### 2단계 — Few-Shot 적용

입력-출력 예시를 제공한 경우다. 모델이 예시에서 형식, 톤, 길이 패턴을 파악하여 동일하게 적용한다.

**System**

```
당신은 유능한 어시스턴트입니다.
- 아래 예시의 톤과 형식으로 작성하세요.

###
테크닉: Negative Prompting
소개 문구: "하지 말아야 할 것을 명시할수록
            AI의 출력은 정확해진다.
            원치 않는 패턴을 직접 차단하는
            가장 확실한 제어 방법."
###
테크닉: Role-Specific Prompting
소개 문구: "역할 하나로 AI의 관점이 바뀐다.
            전문성, 어조, 사고방식까지
            한 문장으로 설계하는 기술."

```

**결과**

```
테크닉: Few-Shot Prompting
소개 문구: "백 마디 설명보다 몇 개의 예시가 강력하다.
            원하는 출력의 패턴과 형식을
            AI에게 직관적으로 학습시키는 기술."
```

예시의 톤과 형식을 그대로 따라 짧은 소개 문구 하나만 출력되었다. 불필요한 컨셉 분기, 구조 설명, 팁이 사라졌다.

---

## 프롬프트 구성요소별 역할 분석

| 구성요소   | 내용       | 역할                |
| ------ | -------- | ----------------- |
| 구분자    | ###      | 예시 간 경계를 명확히 구분   |
| 입력 예시  | 테크닉 2개   | 어떤 형태의 입력인지 패턴 전달 |
| 출력 예시  | 소개 문구 2개 | 원하는 톤, 길이, 형식 전달  |
| 새로운 입력 | 스탠딩 데스크  | 모델이 완성해야 할 부분     |

---

## 적용 효과

| 항목      | 1단계 (Zero-Shot) | 2단계 (Few-Shot) |
| ------- | --------------- | -------------- |
| 출력 형식   | 모델이 임의 결정       | 예시와 동일한 형식     |
| 컨셉 수    | 3가지로 분기         | 하나로 통일         |
| 톤       | 제각각             | 예시와 일관된 톤      |
| 불필요한 내용 | 작성 팁 포함         | 소개 문구만 출력      |
| 길이      | 과도하게 김          | 예시와 유사한 길이     |

---

## 핵심 결과

예시 없이 작업 지시만 했을 때 모델은 형식, 톤, 길이를 스스로 판단하여 요청하지 않은 구조와 내용을 자동으로 생성했다.

입력-출력 예시를 2개 제공하자 결과가 달라졌다. 모델이 예시에서 패턴을 파악하여 동일한 형식의 소개 문구 하나만 출력했다. 텍스트로 설명하기 어려운 톤과 문장 리듬까지 예시를 통해 전달되었다.

> 예시 없을 때: 모델이 형식을 스스로 판단 → 의도와 다른 결과
> 
> 예시 2개 제공: 패턴 파악 → 예시와 일관된 형식으로 출력

---

## Few-Shot Prompting 원칙

- **구분자를 명확히** — `###` 같은 구분자로 예시 간 경계를 명확히 해야 모델이 패턴을 정확히 파악한다
- **형식 일관성** — 모든 예시가 동일한 구조를 따라야 한다. 입력/출력 형식이 예시마다 다르면 모델이 혼란을 겪는다
- **수보다 질** — 예시가 많다고 좋은 게 아니다. 원하는 패턴을 명확히 보여주는 2~3개가 더 효과적이다
- **마지막 입력은 비워두기** — 모델이 완성해야 할 부분의 출력은 비워야 한다
