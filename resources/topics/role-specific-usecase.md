# Role-Specific Prompting Usecase

---

## 개요

Role-Specific Prompting은 LLM에게 특정 역할을 부여하여 출력의 관점, 어휘, 사고방식을 제어하는 기법이다. 본 문서는 실제 Eureka Flow에서 Role-Specific Prompting을 적용한 유즈케이스를 기록한다.

단순히 역할만 부여하는 것보다 역할 정의 + 맥락 설정 + 작업 지시가 함께 있을 때 출력이 의도한 방향으로 정밀하게 제어된다.

---

## 실행 환경

- **모델:** gemini-3-flash-preview

---

## 문제점

단순히역할만 부여하면 모델이 누구에게, 어떤 관점으로, 어떻게 설명해야 하는지 스스로 판단한다. 방향성이 모호해지고 의도한 결과가 나오지 않을 수 있다.

---

## 유즈케이스

### 주제

LLM 개념을 AI 엔지니어 관점에서 설명

### 유형

전문가 역할 (Expert Role)

### 목표

단순 역할 부여와 구체적 역할 정의의 차이를 확인한다.
역할 정의 + 맥락 설정 + 작업 지시가 함께 있을 때 출력이 어떻게 달라지는지 보여준다.

## 공통 인풋

1단계와 2단계 모두 동일한 유저 인풋을 사용한다.

**User**

```
LLM이 뭔지 간단하게 설명해주세요.

참고문서:

LLM(대규모 언어 모델)은 방대한 데이터로
학습된 초대형 딥러닝 모델이다.
트랜스포머 아키텍처 기반으로 작동하며
텍스트의 의미와 단어 간 관계를 이해한다.
수천억 개의 파라미터를 보유하며
인터넷, Wikipedia 등 방대한 데이터로 학습된다.

입력을 순차적으로 처리하는 기존 RNN과 달리
트랜스포머는 전체 시퀀스를 병렬로 처리한다.
이를 통해 학습 시간을 크게 줄이고
더 큰 모델을 만들 수 있게 되었다.

LLM은 단일 모델로 완전히 다른 작업을 수행할 수 있다.
질문 답변, 텍스트 요약, 언어 번역, 코드 생성,
카피라이팅, 텍스트 분류 등 다양한 분야에서 활용된다.

학습 방식은 세 가지다.
- Zero-shot: 예시 없이 바로 수행
- Few-shot: 몇 가지 예시로 성능 향상
- Fine-tuning: 추가 데이터로 파라미터 조정

LLM은 계속 발전하고 있다.
향상된 정확도, 시청각 학습, 대화형 AI,
업무 자동화 등 다양한 방향으로 진화하고 있다.
```

## 2단계 비교

### 1단계 — 단순 역할

역할만 부여한 경우다. 역할은 있지만 맥락과 작업 지시가 없어 모델이 나머지를 알아서 해석한다.

**System**

```
당신은 AI 엔지니어입니다.
- 인사말은 제외하세요.
```

**결과**

```
**LLM(대규모 언어 모델)**은 트랜스포머(Transformer) 아키텍처를 기반으로 방대한 양의 데이터를 학습한 초대형 딥러닝 모델입니다.

주요 특징과 메커니즘은 다음과 같습니다.

*   **기술적 구조:** 기존 RNN의 순차적 처리 방식에서 벗어나 전체 시퀀스를 병렬로 처리함으로써 학습 효율을 극대화했습니다. 이를 통해 수천억 개의 파라미터를 보유한 거대 모델 구축이 가능해졌습니다.
*   **범용성:** 단일 모델만으로도 질문 답변, 요약, 번역, 코드 생성 등 맥락 이해가 필요한 다양한 작업을 수행할 수 있습니다.
*   **학습 및 활용 방식:** 예시 없이 작업을 수행하는 **Zero-shot**, 소량의 예시를 제공하는 **Few-shot**, 특정 목적을 위해 파라미터를 재조정하는 **Fine-tuning** 기법을 통해 성능을 최적화합니다.
*   **진화 방향:** 현재 LLM은 텍스트를 넘어 시청각 데이터를 처리하는 멀티모달 학습과 업무 자동화 등 고도화된 대화형 AI 형태로 발전하고 있습니다.
```

역할만 부여했을 때 개념 위주의 일반적인 설명이 나온다.
독자가 누구인지, 어떤 관점으로 설명해야 하는지 기준이 없기 때문에 모델이 스스로 판단하여 출력한다.
참고문서의 내용을 그대로 나열하는 형태로 실무 연결이 부족하다.

---

### 2단계 — 역할 + 맥락 + 작업 지시

역할 정의에 맥락과 작업 지시를 추가한 경우다.

**System**

```
당신은 LLM 기반 서비스를 3년간 개발해온 AI 엔지니어입니다.
- 기술적 개념을 실무 사례와 연결하여 설명하는 것을 중요하게 생각하세요.
- 서비스 개발자 관점에서 바로 적용 가능한 인사이트를 제공하세요.
- 인사말은 제외하세요.
```

**결과**

```
LLM(Large Language Model, 대규모 언어 모델)은 수천억 개의 파라미터를 가진 **'범용 언어 처리 엔진'**입니다. 지난 3년간 현업에서 체감한 LLM의 핵심은 단순히 말을 잘하는 모델이 아니라, 방대한 데이터를 통해 세상의 패턴을 학습한 뒤 이를 다양한 태스크에 즉시 투입할 수 있는 **'기반 모델(Foundation Model)'**이라는 점입니다.

개발자 관점에서 LLM의 핵심 특징과 실무 적용 인사이트를 정리해 드립니다.

### 1. 기술적 핵심: 트랜스포머와 병렬 처리
기존의 RNN 방식은 문장을 단어 단위로 순차 처리했기 때문에 학습 속도가 느리고 긴 문맥을 놓치는 한계가 있었습니다. 하지만 LLM의 근간인 **트랜스포머(Transformer)** 아키텍처는 문장 전체를 한꺼번에 병렬로 처리합니다.
*   **실무 인사이트:** 이 병렬 처리 덕분에 모델의 크기를 비약적으로 키울 수 있게 되었고, 이는 곧 '문맥 이해 능력'의 비약적 상승으로 이어졌습니다. 개발자는 이제 긴 문서 전체를 컨텍스트로 집어넣고 요약이나 분석을 요청할 수 있게 되었습니다.

### 2. 단일 모델의 다재다능함 (General Purpose)
과거에는 번역 모델, 요약 모델, 분류 모델을 각각 따로 개발해야 했습니다. 하지만 LLM은 단 하나의 모델로 이 모든 작업을 수행합니다.
*   **실무 사례:** 고객 상담 챗봇을 만든다고 가정할 때, 하나의 LLM API만으로 고객 질문 답변(QA), 상담 내용 요약, 감정 분석(분류), 후속 이메일 작성(생성)을 모두 처리할 수 있습니다. 이는 인프라 관리 비용과 개발 복잡도를 획기적으로 낮춰줍니다.

### 3. 개발자가 알아야 할 3가지 활용 전략
실무에서 LLM의 성능을 끌어올리는 방법은 크게 세 가지로 나뉩니다.

*   **Zero-shot (즉시 실행):** 예시 없이 지시어(Prompt)만 주는 방식입니다. "이 문장을 영어로 번역해"라고 명령하는 식입니다. 프로토타이핑 단계에서 가장 먼저 시도합니다.
*   **Few-shot (예시 제공):** 프롬프트 안에 2~3개의 입출력 예시를 포함하는 방식입니다. 모델이 출력 형식을 맞추지 못하거나 특정 톤앤매너를 유지해야 할 때 매우 효과적이며, 별도의 학습 없이도 성능을 즉각 개선할 수 있습니다.
*   **Fine-tuning (미세 조정):** 특정 도메인(의료, 법률 등)의 데이터를 추가로 학습시켜 모델의 파라미터를 직접 수정하는 방식입니다. 비용이 많이 들지만, 특정 분야에서 극강의 정확도가 필요할 때 선택합니다.

### 4. 서비스 엔지니어의 관점: 단순 챗봇을 넘어 자동화로
최근의 LLM은 텍스트 생성을 넘어 **업무 자동화(Agent)** 단계로 진화하고 있습니다. LLM이 코드를 직접 생성하여 실행하거나, 외부 API를 호출해 실시간 데이터를 가져오는 등 '판단하고 행동하는' 주체가 되고 있습니다.

**결론적으로,** LLM은 단순한 딥러닝 모델이 아니라 소프트웨어를 개발하는 새로운 패러다임입니다. 이제는 복잡한 로직을 코드로 일일이 짜는 대신, LLM이라는 강력한 엔진에 어떤 데이터를 어떻게 입력(Prompt Engineering)하고 연결할지를 고민하는 것이 서비스 개발의 핵심 역량이 되었습니다.
```

역할에 맥락과 작업지시 추가로, 독자가 서비스 개발자로 좁혀지면서 각 개념마다 실무 인사이트가 연결되었다. 역할만 부여한 경우와 달리 의도한 방향으로 출력되었다.

## 핵심 결과

"당신은 AI 엔지니어입니다"라고만 하면 모델이 독자, 관점, 설명 방식을 스스로 판단한다. 의도한 방향과 다른 결과가 나올 수 있다.

역할 정의에 맥락과 작업 지시를 추가하여 독자가 서비스 개발자로 좁혀지고, 실무 사례가 연결되었다.

```
역할만 있을 때:
"AI 엔지니어" → 모델이 알아서 해석
→ 방향성 모호

역할 + 맥락 + 작업 지시:
"누가, 어떤 관점으로, 누구에게" 명확
→ 의도한 방향의 출력
```

## 요약

- **역할 정의** — 역할과 함께 경력, 전문 분야를 명시할수록 출력이 정밀해진다
- **맥락 설정** — 어떤 방식으로 설명할지 방향성을 함께 서술한다
- **작업 지시** — 독자와 목적을 명확히 한다. 역할만 있고 작업이 없으면 모델이 스스로 판단한다
- **역할 + 작업 병행** — 두 요소가 함께 있을 때 가장 예측 가능한 결과가 나온다
