# 8 Techniques of Prompt Engineering

LLM의 출력 품질을 최적화하기 위해서는 단순한 질의(Zero-shot)를 넘어 모델의 추론 메커니즘과 정렬 특성을 고려한 구조적 접근이 필요합니다. 

## Few-Shot Prompting (퓨샷 프롬프팅)

**Few-Shot Prompting**은 **LLM**에 몇 가지 **입력-출력 예시(Input-Output pairs)**를 데모로 제공하여 모델이 **문맥 내 학습(In-Context Learning, ICL)**을 통해 패턴을 파악하고 새로운 입력에 적용하도록 유도하는 기술입니다. 이 기법은 모델이 **Zero-Shot**으로 해결하기 어려운 복잡한 작업이나 고유한 응답 형식이 필요한 문제에서 성능을 크게 향상시킵니다.

- **Format Consistency (형식 일관성)**: 예시들과 최종 질문 사이의 구조적 일관성을 유지하기 위해 **구분자(Delimiters, ###, --- 등)**를 명확히 사용하는 것이 중요합니다.
- **Label Distribution (레이블 분포)**: 예시에서 특정 레이블이 과하게 많으면 모델이 해당 레이블로 편향될 수 있으므로 실제 분포를 반영하거나 무작위로 배치하는 것이 **강건성(Robustness)** 향상에 기여합니다.

## Chain-of-Thought (CoT) Prompting

**Chain-of-Thought (CoT) Prompting**은 복잡한 문제를 풀 때 최종 응답을 내놓기 전 **중간 추론 단계(Intermediate reasoning steps)**를 거치도록 요청하여 모델의 논리적 능력을 극대화하는 기법입니다. 추론 과정을 단계별로 분해함으로써 모델은 더 많은 **계산 자원(Computation)**을 할당할 수 있게 되고, 스스로 오류를 수정할 기회(**Error correction**)를 얻게 됩니다.

- **Zero-Shot CoT**: 별도의 예시 없이 프롬프트 끝에 "**단계별로 생각해보자(Let's think step by step)**"라는 문구만 추가하여 모델의 추론 회로를 활성화합니다.
- **Self-Consistency (자기 일관성)**: 여러 개의 추론 경로를 샘플링한 후, 가장 빈번하게 나오는 답을 선택하여 답변의 일관성과 정확도를 높입니다.

## Prompt Hierarchy (프롬프트 계층 구조)

**Prompt Hierarchy**는 지침의 출처에 따라 우선순위를 정하는 보안 및 제어 프레임워크로, 일반적으로 **System > Developer > User > Tool** 순서로 권한 계층이 구성됩니다. 이 구조의 핵심은 신뢰할 수 있는 시스템 명령이 신뢰할 수 없는 사용자 입력이나 외부 데이터보다 우선하도록 강제하여 **프롬프트 주입(Prompt Injection)** 공격을 방어하는 데 있습니다.

- **Security: 하위 계층의 명령이 상위 계층의 제약 조건과 충돌할 경우 모델이 상위 명령을 따르도록 함으로써 모델의 안전성과 조종 가능성(Steerability)을 높입니다.

## Role-Based Prompting (역할 기반 프롬프팅)

**Role-Based Prompting**은 사전 학습된 모델 내에 압축된 다양한 **페르소나(Persona)** 중 특정 매개변수 하위 공간을 활성화하는 방식입니다. 모델에게 "당신은 보안 연구원입니다"와 같이 특정 역할을 부여함으로써 모델의 행동 기대치를 설정하고 관련 지식 도메인을 우선적으로 참조하게 유도합니다.
이는 관련 지식 도메인을 활성화하고 출력 형식의 관례를 수립하는 데 효과적이지만, 단순히 역할을 부여하는 것보다는 구체적인 작업을 명시하는 것이 더 신뢰할 수 있는 결과를 낳는 경우가 많습니다.

## Negative Prompting

**모델이 생성하지 말아야 할 것(Anti-patterns)이나 피해야 할 제약 조건을 명시적으로 규정하는 기법입니다.** "간결하게 작성해"라는 긍정 지시보다 "**불필요한 수식어나 전문은 포함하지 마**"와 같이 구체적인 부정 제약을 사용하는 것이 모델을 원치 않는 결과물로부터 멀어지게 하는 데 더 효과적입니다.

이론적으로 긍정적 선호는 맥락에 따라 모호할 수 있지만, 부정적 제약은 독립적으로 검증 가능하고 명확한 경계를 형성하므로 AI의 행동을 인간의 입장과 일치시키는 과정인 AI 정렬(Alignment) 관점에서 더 견고한 접근법으로 평가받습니다.

## JSON Prompting

**JSON Prompting**은 프롬프트 끝에 명확한 **JSON 스키마(Schema)**를 정의하여 모델이 기계 판독이 가능한 구조화된 응답을 반환하도록 강제하는 기술입니다. 이는 LLM을 외부 시스템이나 API에 통합할 때 필수적인 기능입니다.

- **Output Contract: "**오직 JSON만 반환하라(Return ONLY)**"는 문구와 함께 스키마를 프롬프트의 마지막에 배치하여 모델의 서술형 응답을 방지합니다.
- **Thought of Structure (ToS)**: 모델이 JSON을 생성하기 전 데이터 구조에 대해 먼저 추론하도록 하여 복잡한 스키마 준수율을 높일 수 있습니다.
- **Verification (검증)**: 출력 후에는 **Zod**와 같은 라이브러리를 사용해 데이터 형상을 검증하거나  실패 시 재시도 루프를 구성하여 시스템의 신뢰성을 확보하는 것이 권장됩니다.

## Attentive Reasoning Queries (ARQ)

ARQ는 **자유 형식의 CoT 대신 JSON 스키마 내에 인코딩된 특정 도메인 질문을 통해 모델의 추론 과정을 단계별로 제어하는 구조화된 접근법입니다.** 이 기법은 긴 대화나 복잡한 에이전틱(Agentic) 시나리오 도중 모델이 잊기 쉬운 중요한 지침을 다시 상기시키고, 추론 단계를 세분화하여 최종 결정이 검증 가능하도록 도우며 특히, 할루시네이션(Hallucination) 방지와 지침 준수에 탁월합니다.

## Verbalized Sampling (언어화된 샘플링)

**모델 정렬 과정(RLHF)에서 발생하는 '모드 붕괴(Mode Collapse)' 현상, 즉 응답의 다양성이 극도로 줄어드는 문제를 해결하기 위해 고안된 기법입니다. 

- 작동 원리: 모델에게 하나의 답변만 요구하는 대신 여러 개의 후보 응답을 생성하고 각 응답에 대해 모델 스스로 판단한 **확률 점수(Probability Scores)**를 함께 출력하도록 지시합니다.
- **Effect (주요 효과)**: 직접 프롬프팅 대비 **다양성을 2~3배 향상**시키며 창의적 글쓰기나 시뮬레이션 작업에서 사전 학습 단계의 풍부한 표현력을 복원합니다. 또한 정확도나 안전성을 해치지 않으면서도 출력의 다양성을 사용자가 조절할 수 있습니다.
