# Verbalized Sampling

## 1. 개요 및 배경

대규모 언어 모델(LLM)은 사전 학습(Pre-training) 단계에서 방대한 텍스트를 학습하며 풍부하고 다양한 표현력을 갖추게 된다. 그러나 이후 인간의 피드백을 기반으로 한 강화 학습인 RLHF(Reinforcement Learning from Human Feedback) 과정을 거치면서 모델은 점점 "안전하고 무난한" 응답을 선호하는 방향으로 조정된다. 이 과정에서 모델이 생성할 수 있는 응답의 다양성이 급격히 줄어드는  **Mode Collapse(모드 붕괴)** 현상이 발생한다.

Mode Collapse란 모델이 다양한 가능성을 탐색하는 대신 확률적으로 가장 안전하고 평균적인 응답만을 반복적으로 생성하게 되는 현상이다. 창의적 글쓰기, 아이디어 발산, 시뮬레이션처럼 다양한 관점과 표현이 필요한 작업에서 이 현상은 심각한 품질 저하로 이어진다.

**Verbalized Sampling은 바로 이 문제를 해결하기 위해 고안된 기법이다. 모델에게 하나의 답변만 요구하는 대신 여러 개의 후보 응답을 생성하고, 각 응답에 대해 모델 스스로 판단한 확률 점수를 함께 출력하도록 지시한다. 이를 통해 직접 프롬프팅 대비 다양성을 2~3배 향상시키며, 창의적 글쓰기나 시뮬레이션 작업에서 사전 학습 단계의 풍부한 표현력을 복원한다. 또한 정확도나 안전성을 해치지 않으면서도 출력의 다양성을 사용자가 직접 조절할 수 있다는 점에서 실무적 가치가 높다.

이 기법은 LLM API의 temperature나 top-p 같은 파라미터를 직접 조정할 수 없는 환경, 즉 프롬프트 수준에서만 모델을 제어해야 하는 상황에서 특히 유용하다. 샘플링 파라미터를 자연어 지시로 대체하는 방식이기 때문에, 기술적 접근 권한 없이도 출력의 다양성과 탐색 범위를 실질적으로 제어할 수 있다.

> **핵심 정의**
> 
> Verbalized Sampling이란, LLM에게 단일 응답 대신 여러 개의 후보 응답을 생성하게 하고, 각 응답에 모델이 스스로 평가한 확률 점수나 신뢰도를 함께 출력하도록 유도하는 프롬프트 설계 전략이다. 이를 통해 Mode Collapse로 인해 억제된 출력 다양성을 복원하고, 사용자가 다양성의 수준을 언어적 지시로 제어할 수 있게 한다.
> 
> **핵심 공식:** Verbalized Sampling = 다중 후보 생성 요청 + 확률 점수 출력 지시 + 사용자 선택 또는 집계
> 
> 예시: _"아래 주제에 대한 도입 문장을 5가지 다른 스타일로 작성하고, 각각에 대해 독창성 점수를 0~1 사이로 평가하시오."_

## 2. 이론적 배경

###  Mode Collapse의 발생 원인

Mode Collapse를 이해하려면 먼저 RLHF 과정을 살펴봐야 한다. RLHF는 모델이 생성한 여러 응답 중 인간 평가자가 선호하는 응답을 학습하여 모델의 행동을 조정하는 방식이다. 이 과정은 모델이 유해하거나 부정확한 응답을 생성하지 않도록 안전성을 높이는 데 효과적이지만, 동시에 의도치 않은 부작용을 낳는다.

인간 평가자는 일반적으로 명확하고 무난하며 예측 가능한 응답을 선호하는 경향이 있다. 이 선호가 누적되면 모델은 점점 "평균적으로 좋은 응답"의 방향으로 수렴하게 되고, 사전 학습 단계에서 갖추었던 다양한 표현 방식, 비관습적인 관점, 실험적인 문체 등이 억제된다. 결과적으로 모델은 다양한 가능성의 분포(Distribution) 전체를 탐색하는 대신, 확률 질량이 집중된 좁은 영역의 응답만을 반복적으로 생성하게 된다.
### Verbalized Sampling의 작동 원리

Verbalized Sampling은 Mode Collapse 문제를 프롬프트 수준에서 우회하는 접근이다. 핵심 아이디어는 두 가지다.

첫째, **다중 후보 생성 강제**다. 단일 응답을 요청하면 모델은 가장 확률이 높은 하나의 경로를 따르지만, 여러 개의 서로 다른 응답을 요청하면 모델은 자연스럽게 다양한 가능성을 탐색해야 한다. "5가지 다른 방식으로 작성하시오"처럼 다양성 자체를 명시적으로 요구하면, 모델은 이미 선택한 경로와 겹치지 않는 새로운 경로를 찾아야 하기 때문에 더 넓은 파라미터 공간을 탐색하게 된다.

둘째, **확률 점수의 언어화(Verbalization)**다. 일반적으로 LLM API에서 토큰의 생성 확률은 로그 확률(Log-probability) 형태로 별도의 기술적 접근을 통해서만 얻을 수 있다. Verbalized Sampling은 모델에게 각 후보 응답에 대한 자체 평가 점수를 자연어로 출력하도록 지시함으로써, 기술적 접근 없이도 유사한 정보를 얻는다. 모델이 "이 응답의 창의성 점수: 0.85"처럼 출력하면, 이는 모델의 내부 확신도를 언어적으로 외현화한 것이다.

### 확률 점수의 의미와 해석

Verbalized Sampling에서 모델이 출력하는 확률 점수는 실제 수학적 확률과 동일하지 않다. 이것은 모델이 자체적으로 추론한 상대적 신뢰도나 적합도를 숫자로 표현한 것으로, 모델의 내부 판단을 언어적으로 근사(Approximate)한 값이다.

이 점수는 몇 가지 방식으로 활용할 수 있다. 사용자가 직접 높은 점수의 응답을 선택하거나, 반대로 낮은 점수의 비관습적인 응답을 선택하여 다양성을 탐색하거나, Self-Consistency처럼 여러 응답의 점수를 집계하여 최적의 응답을 도출하는 데 사용할 수 있다. 핵심은 사용자가 단일 출력에 의존하지 않고 출력의 분포를 직접 탐색할 수 있게 된다는 점이다.

### Temperature 파라미터와의 관계

LLM의 출력 다양성을 제어하는 가장 직접적인 방법은 temperature 파라미터를 조정하는 것이다. Temperature가 높을수록 모델은 낮은 확률의 토큰도 선택하게 되어 더 다양하고 창의적인 출력이 나오지만, 동시에 일관성이 떨어질 수 있다. Temperature가 낮을수록 출력은 일관되지만 단조로워진다.

Verbalized Sampling은 이 temperature 조정을 프롬프트 수준에서 언어적으로 구현하는 방식으로 볼 수 있다. "매우 창의적이고 실험적인 방식으로", "보수적이고 안전한 방식으로"처럼 다양성의 수준을 자연어로 지시함으로써, API 파라미터에 직접 접근하지 않아도 유사한 효과를 얻는다. 이는 프롬프트만으로 모델을 제어해야 하는 환경에서 특히 중요한 특성이다.

## 3. 주요 유형 및 적용 방식

Verbalized Sampling은 어떤 방식으로 다양성을 요청하고 점수를 출력하는가에 따라 여러 유형으로 분류된다.

### 3-1. 다중 후보 + 점수 출력 방식

가장 기본적인 형태로, 여러 개의 후보 응답을 생성하고 각각에 대한 점수를 함께 출력하도록 지시하는 방식이다. 점수의 기준은 작업의 목적에 따라 창의성, 적합성, 명확성, 독창성 등 다양하게 설정할 수 있다.

이 방식의 핵심은 후보 응답들이 서로 충분히 다르도록 강제하는 것이다. 단순히 "5가지 응답을 작성하시오"라고만 하면 모델이 유사한 응답을 반복할 수 있기 때문에, "각 응답은 서로 다른 관점이나 스타일을 사용하시오"처럼 다양성 자체를 명시적으로 요구하는 지시를 함께 포함해야 한다.

> **기본 프롬프트 구조**
> 
> "아래 주제에 대한 첫 문장을 5가지 서로 다른 스타일로 작성하시오. 각 응답 뒤에 해당 응답의 독창성 점수를 0.0~1.0 사이로 평가하여 표시하시오. 5가지 응답은 문체, 관점, 어조 면에서 서로 명확히 구분되어야 한다."

### 3-2. 다양성 수준 지정 방식

사용자가 원하는 다양성의 수준을 명시적으로 지정하여, 출력의 탐색 범위를 언어적으로 제어하는 방식이다. "보수적", "균형적", "실험적"처럼 다양성의 스펙트럼을 레이블로 정의하고, 그에 맞는 응답을 요청한다.

이 방식은 사용자가 상황에 따라 다양성과 안전성의 균형을 유연하게 조정할 수 있다는 장점이 있다. 법적 문서처럼 일관성이 중요한 작업에는 낮은 다양성 레이블을, 창의적 브레인스토밍처럼 다양한 아이디어가 필요한 작업에는 높은 다양성 레이블을 적용한다.

> **다양성 수준 지정 예시**
> 
> "아래 제품 슬로건 아이디어를 세 가지 수준으로 제시하시오.
> 
> - 안전한 버전(p=0.3): 검증된 표현 방식, 예측 가능한 구조
> - 균형적 버전(p=0.6): 익숙하지만 차별화된 요소 포함
> - 실험적 버전(p=0.9): 비관습적이고 도전적인 접근
> 
> 각 버전 뒤에 해당 슬로건의 타깃 적합성 점수를 함께 표시하시오."

### 3-3. 자기 평가 기반 선택 방식

모델이 여러 후보를 생성한 후, 스스로 각 후보를 평가하고 최적의 응답을 선택하는 과정까지 수행하게 하는 방식이다. 단순히 후보를 나열하는 것을 넘어, 모델의 자기 평가 능력을 활용하여 최종 결과물의 품질을 높인다.

이 방식은 Chain-of-Thought와 결합될 때 특히 효과적이다. 각 후보를 평가하는 과정에서 모델이 명시적인 기준에 따라 추론하게 함으로써, 단순한 점수 나열보다 더 신뢰할 수 있는 평가 결과를 얻을 수 있다.

> **자기 평가 기반 프롬프트 구조**
> 
> "아래 작업에 대한 응답을 3가지 작성하시오. 그 다음, 각 응답을 명확성(0~10), 설득력(0~10), 간결성(0~10) 기준으로 평가하시오. 마지막으로 종합 점수가 가장 높은 응답을 선택하고 선택 이유를 한 문장으로 설명하시오."

### 3-4. 확률 분포 시각화 방식

여러 후보 응답과 점수를 출력한 후, 이를 구조화된 형태로 정리하여 출력의 분포를 시각적으로 파악할 수 있게 하는 방식이다. JSON 형식이나 표 형식으로 출력하면 후속 처리나 분석이 용이하다.

이 방식은 자동화 파이프라인에서 Verbalized Sampling을 활용할 때 특히 유용하다. 구조화된 출력은 프로그래밍 방식으로 파싱하여 가장 높은 점수의 응답을 자동 선택하거나, 점수 분포를 분석하는 데 활용할 수 있다.

> **구조화된 출력 예시**
> 
> "아래 문장을 3가지 방식으로 재작성하고 결과를 JSON 형식으로 출력하시오:
> 
> \`\`\``json
> {
>   "candidates": [
>     {"id": 1, "text": "...", "creativity": 0.7, "clarity": 0.9},
>     {"id": 2, "text": "...", "creativity": 0.9, "clarity": 0.6},
>     {"id": 3, "text": "...", "creativity": 0.5, "clarity": 0.95}
>   ],
>   "recommended": 1
> }
> \`\`\`"
> \`\`\``

## 4. 도메인별 적용 사례

### 4-1. 창의적 글쓰기 및 콘텐츠 생성

Verbalized Sampling이 가장 직접적인 효과를 발휘하는 분야다. Mode Collapse로 인해 LLM이 반복적으로 유사한 문체와 구조를 사용하는 문제를 해결하여, 사전 학습 단계에서 갖추었던 풍부한 표현력을 복원한다.

블로그 도입 문장 작성에서는 "5가지 서로 다른 어조(유머러스, 학술적, 스토리텔링, 도발적, 간결한)로 도입 문장을 작성하고 각각의 독자 흡인력 점수를 평가하시오"처럼 어조 자체를 다양성의 축으로 설정한다. 마케팅 카피 생성에서는 "감성적 접근, 논리적 접근, 사회적 증거 활용 세 가지 방식으로 카피를 작성하고 각각의 설득력 점수를 함께 제시하시오"처럼 설득 전략을 다양성의 기준으로 삼는다. 소설 장면 묘사에서는 "같은 장면을 1인칭 내적 독백, 3인칭 전지적 시점, 관찰자 시점으로 각각 묘사하고 몰입감 점수를 평가하시오"처럼 서술 시점을 다양성 축으로 활용한다.

> **프롬프트 예시 — 제품 소개 문구 다양화**
> 
> "무선 이어폰 신제품의 소개 문구를 아래 4가지 방향으로 각각 2문장씩 작성하시오. 각 문구 뒤에 브랜드 적합성 점수(0.0~1.0)를 표시하시오.
> 
> 1. 기술적 성능 중심
> 2. 라이프스타일 감성 중심
> 3. 가성비·실용성 중심
> 4. 디자인·심미성 중심
> 
> 네 가지 문구는 어휘와 감성적 호소 방식에서 명확히 구분되어야 한다."

### 4-2. AI 챗봇 및 대화형 서비스

대화형 AI에서 Verbalized Sampling은 사용자에게 선택지를 제공하거나, 내부적으로 여러 응답 후보를 생성한 후 최적의 것을 선택하는 방식으로 활용된다. 단일 응답만 제공하는 일반적인 챗봇과 달리, 다양한 관점이나 접근 방식을 사용자에게 보여줌으로써 더 풍부한 상호작용을 가능하게 한다.

글쓰기 보조 챗봇에서는 사용자가 작성한 문장의 개선 방향을 여러 버전으로 제시하고 각 버전의 특성을 점수와 함께 설명하여, 사용자가 자신의 의도에 맞는 방향을 선택할 수 있게 한다. 아이디어 발산 도구로는 "이 문제에 대한 해결 접근 방식을 5가지 제시하고 각각의 실현 가능성 점수를 평가하시오"처럼 브레인스토밍 과정 자체를 구조화한다.

### 4-3. 이미지 생성 AI 프롬프트 설계

이미지 생성 AI에서 프롬프트의 표현 방식에 따라 결과물이 크게 달라지는데, Verbalized Sampling을 활용하면 동일한 주제에 대해 서로 다른 방향의 프롬프트를 생성하고 각각의 예상 효과를 평가하여 최적의 프롬프트를 선택할 수 있다.

예를 들어 "도시 야경 이미지를 위한 프롬프트를 3가지 스타일(사진 현실주의, 인상주의 회화, 미래 사이버펑크)로 작성하고, 각 프롬프트의 스타일 명확성 점수를 평가하시오"처럼 Verbalized Sampling을 프롬프트 생성 단계에 적용한다. 이를 통해 실제 이미지를 여러 번 생성해보기 전에 프롬프트 수준에서 방향을 탐색하고 선택할 수 있다.

### 4-4. 코드 생성 및 솔루션 탐색

코드 생성에서 Verbalized Sampling은 동일한 문제를 여러 알고리즘이나 접근 방식으로 해결하는 후보를 생성하고, 각 접근 방식의 장단점을 평가하는 데 활용된다.

"아래 정렬 문제를 3가지 다른 알고리즘으로 구현하고, 각각의 시간 복잡도 적합성 점수와 코드 가독성 점수를 함께 제시하시오"처럼 기술적 평가 기준을 점수화하여, 개발자가 상황에 맞는 구현 방식을 선택할 수 있게 한다. 또한 "이 버그의 원인을 3가지 가능성으로 제시하고 각각의 발생 가능성 점수를 평가하시오"처럼 디버깅 과정에서도 Verbalized Sampling을 활용하여 원인 탐색의 효율성을 높인다.

### 4-5. 시뮬레이션 및 시나리오 분석

Verbalized Sampling은 하나의 상황에 대해 여러 시나리오를 탐색해야 하는 시뮬레이션 작업에서 특히 효과적이다. 단일 응답에 의존하면 가장 일반적인 시나리오만 출력되지만, Verbalized Sampling을 적용하면 낙관적, 비관적, 중립적 시나리오를 동시에 탐색할 수 있다.

"이 프로젝트의 6개월 후 상황을 낙관적 시나리오(p=0.3), 현실적 시나리오(p=0.5), 비관적 시나리오(p=0.2) 세 가지로 제시하고, 각 시나리오의 발생 가능성 점수를 함께 표시하시오"처럼 확률 분포 자체를 시나리오 설계에 반영한다. 이를 통해 단일 예측에 의존하지 않고 가능한 미래의 분포를 탐색하는 더 견고한 의사결정을 지원한다.

## 5. 다른 프롬프트 기법과의 결합

Verbalized Sampling은 다른 프롬프트 기법과 결합할 때 각 기법의 약점을 보완하고 더 강력한 효과를 발휘한다.

### 5-1. Verbalized Sampling + Chain-of-Thought

각 후보 응답을 생성할 때 단계별 추론 과정을 함께 출력하게 하는 방식이다. 단순히 여러 응답을 나열하는 것이 아니라, 각 응답이 어떤 추론 경로를 통해 도출되었는지를 명시함으로써 사용자가 응답의 질을 더 깊이 평가할 수 있게 한다.

이 결합은 Self-Consistency와 유사하지만, 추론 과정이 투명하게 공개된다는 점에서 차이가 있다. 사용자는 점수뿐만 아니라 추론 경로 자체를 비교하여 더 신뢰할 수 있는 응답을 선택할 수 있다.

> **결합 프롬프트 예시**
> 
> "아래 비즈니스 문제에 대한 해결 방안을 3가지 제시하시오. 각 방안에 대해 문제 분석 → 핵심 가정 → 예상 효과 순서로 추론 과정을 작성하고, 마지막에 실현 가능성 점수(0.0~1.0)를 표시하시오. 세 가지 방안은 서로 다른 전략적 관점에서 도출되어야 한다."

### 5-2. Verbalized Sampling + Role-Based Prompting

서로 다른 역할의 전문가 관점에서 후보 응답을 생성하는 방식이다. 역할이 다양성의 축을 제공하고, Verbalized Sampling이 각 역할의 관점에서 도출된 응답을 평가하는 구조다.

예를 들어 "마케터, 엔지니어, 디자이너의 관점에서 각각 이 기능에 대한 우선순위 의견을 제시하고, 각 관점의 비즈니스 임팩트 점수를 평가하시오"처럼 역할이 다양성의 차원을 구성한다. 하나의 문제에 대해 다양한 전문가 시각을 동시에 탐색할 수 있어, 다각도 분석이 필요한 의사결정에서 특히 유용하다.

### 5-3. Verbalized Sampling + Negative Prompting

다양한 후보를 생성하면서 동시에 각 후보가 피해야 할 패턴을 명시적으로 금지하는 방식이다. 다양성을 추구하면서도 품질의 하한선을 설정하는 이중 제어가 가능하다.

"5가지 서로 다른 방식으로 작성하되, 각 버전은 과장 표현, 진부한 클리셰, 반복적인 문장 구조를 포함하지 마시오. 각 버전의 신선도 점수를 평가하시오"처럼, 다양성을 확보하면서 동시에 공통적인 품질 기준을 유지한다.

### 5-4. Verbalized Sampling + JSON Prompting

구조화된 JSON 형식으로 여러 후보와 점수를 출력하게 하는 방식이다. 자동화 파이프라인에서 Verbalized Sampling 결과를 프로그래밍 방식으로 처리해야 할 때 특히 유용하다. 가장 높은 점수의 응답을 자동 선택하거나, 점수 분포를 분석하는 후속 처리를 코드로 구현할 수 있다.

## 6. 장점과 한계

### 장점

Verbalized Sampling의 가장 핵심적인 강점은 **Mode Collapse 문제의 실용적 해결**이다. RLHF 정렬 과정에서 억제된 출력 다양성을 별도의 모델 수정 없이 프롬프트 수준에서 복원할 수 있다. 직접 프롬프팅 대비 다양성을 2~3배 향상시킨다는 점은 창의적 작업에서 특히 중요한 의미를 갖는다.

**사용자 제어 가능성**도 핵심 강점이다. temperature 파라미터처럼 API 수준의 기술적 접근 없이도, 자연어 지시만으로 출력의 다양성 수준을 유연하게 조정할 수 있다. 낮은 다양성이 필요한 작업과 높은 다양성이 필요한 작업에 동일한 모델을 사용하면서 출력의 성격을 자유롭게 전환할 수 있다.

**투명성과 선택 가능성**도 중요한 장점이다. 단일 출력에 의존하지 않고 여러 후보와 그에 대한 평가 점수를 함께 제공받음으로써, 사용자가 자신의 목적에 맞는 응답을 직접 선택할 수 있다. 이는 LLM을 일방적인 답변 생성 도구가 아니라 탐색 공간을 함께 탐험하는 파트너로 활용하는 방식이다.

**안전성 유지**도 주목할 만한 특성이다. 다양성을 높이는 다른 방법, 예를 들어 temperature를 과도하게 높이는 방식은 출력의 일관성과 안전성을 저하시킬 수 있다. 반면 Verbalized Sampling은 자연어 지시의 범위 안에서 다양성을 탐색하기 때문에 모델의 안전 가이드라인을 유지하면서도 다양성을 확보할 수 있다.

### 한계 및 주의사항

가장 근본적인 한계는 **점수의 불확실성**이다. 모델이 출력하는 확률 점수는 실제 수학적 확률이 아니라 모델의 자기 평가를 언어적으로 근사한 값이다. 이 점수가 항상 실제 응답 품질과 일치하지 않을 수 있으며, 모델이 자신의 출력을 과대 또는 과소 평가하는 경향이 있다. 점수를 절대적 기준으로 신뢰하기보다 상대적 비교의 참고 지표로 활용하는 것이 바람직하다.

**토큰 비용 증가**도 중요한 한계다. 단일 응답 대신 여러 후보를 생성하므로 출력 토큰 수가 후보 수에 비례하여 증가한다. 5개의 후보를 요청하면 단일 응답 대비 약 5배의 토큰이 소비된다. 비용 효율을 고려하여 Verbalized Sampling이 실제로 필요한 작업에만 선택적으로 적용해야 한다.

**후보 간 유사성 문제**도 실무에서 자주 마주치는 한계다. "서로 다르게 작성하시오"라고 지시해도 모델이 표면적으로는 다르지만 내용적으로 유사한 후보를 생성하는 경우가 있다. 이를 방지하기 위해 다양성의 기준을 더 구체적으로 명시하거나, Negative Prompting과 결합하여 이전 후보와 유사한 접근을 금지하는 지시를 추가하는 것이 필요하다.

**모델 의존성**도 고려해야 할 점이다. Verbalized Sampling의 효과는 모델의 자기 평가 능력에 의존한다. 자기 평가 능력이 충분히 발달하지 않은 소형 모델에서는 점수가 무의미하거나 일관성이 없는 경우가 있다. 사용하는 모델의 특성을 파악하고 점수의 신뢰성을 먼저 검증하는 과정이 필요하다.

## 7. 모범 작성 가이드라인

### 7-1. 다양성 기준 명확화 원칙 — 무엇이 달라야 하는지 구체적으로 지정하라

단순히 "다르게 작성하시오"라는 지시는 모델이 표면적인 어휘만 바꾼 유사한 응답을 생성하는 원인이 된다. 다양성의 차원을 구체적으로 정의해야 한다.

문체, 어조, 관점, 논리 구조, 감성적 호소 방식, 서술 시점처럼 응답이 달라야 하는 구체적인 축을 명시하면 모델이 실질적으로 다른 방향을 탐색하게 된다. "5가지 서로 다른 응답"보다 "감성적 접근, 논리적 접근, 유머러스한 접근, 도발적 접근, 미니멀한 접근으로 각각 작성하시오"처럼 다양성의 차원을 사전에 정의하는 것이 효과적이다.

### 7-2. 점수 기준 명시 원칙 — 무엇을 평가하는지 명확히 정의하라

모델에게 점수를 출력하게 할 때, 평가 기준이 모호하면 점수가 의미 없는 숫자가 된다. 독창성, 명확성, 설득력, 실현 가능성처럼 평가 기준을 작업 목적에 맞게 구체적으로 정의하고, 점수의 범위와 의미를 함께 설명해야 한다.

여러 기준을 동시에 평가할 때는 각 기준의 가중치를 명시하거나, 종합 점수 계산 방식을 지정하면 더 일관된 평가 결과를 얻을 수 있다. "창의성(40%)과 실용성(60%)을 가중 평균하여 종합 점수를 계산하시오"처럼 평가 방식 자체를 프롬프트에 포함하는 것이 효과적이다.

### 7-3. 적정 후보 수 원칙 — 비용과 다양성의 균형을 맞춰라

후보 수가 많을수록 더 넓은 탐색 공간을 커버할 수 있지만, 토큰 비용도 그에 비례하여 증가한다. 일반적으로 3~5개의 후보가 비용과 다양성의 균형을 맞추는 실용적인 범위다.

작업의 중요도와 창의성 요구 수준에 따라 후보 수를 조정하는 것이 바람직하다. 빠른 초안 작성에는 3개, 중요한 마케팅 카피나 핵심 의사결정에는 5~7개, 광범위한 브레인스토밍에는 10개 이상을 고려할 수 있다.

### 7-4. 구조화된 출력 원칙 — 후속 처리를 고려한 형식을 설계하라

Verbalized Sampling의 결과를 어떻게 활용할 것인지에 따라 출력 형식을 설계해야 한다. 사람이 직접 검토할 경우에는 번호와 레이블이 있는 목록 형식이, 자동화 파이프라인에서 처리할 경우에는 JSON 형식이 적합하다.

출력 형식을 명확히 지정하지 않으면 모델이 매번 다른 형식으로 출력하여 일관된 처리가 어려워진다. Negative Prompting과 결합하여 원하지 않는 형식을 금지하고, JSON Prompting과 결합하여 파싱 가능한 구조를 강제하는 것이 실무적으로 효과적이다.

### 7-5. 점수 검증 원칙 — 점수를 맹목적으로 신뢰하지 마라

모델이 출력하는 점수는 절대적 기준이 아니라 상대적 참고 지표다. 특히 처음 Verbalized Sampling을 적용하는 작업에서는 모델이 출력한 점수가 실제 품질과 어느 정도 일치하는지 직접 검증하는 과정이 필요하다.

점수가 높은 응답이 반드시 최선의 선택이 아닐 수 있으며, 점수가 낮은 응답이 오히려 특정 맥락에서 더 적합할 수 있다. 점수는 선택의 출발점으로 활용하되, 최종 판단은 사용자가 내리는 구조를 유지하는 것이 바람직하다.

---

Verbalized Sampling은 RLHF 정렬 과정에서 발생하는 Mode Collapse 문제를 프롬프트 수준에서 실용적으로 해결하는 기법이다. 여러 후보 응답을 생성하고 각각에 대한 확률 점수를 언어적으로 출력하게 함으로써, 기술적 파라미터 조정 없이도 출력 다양성을 복원하고 사용자가 직접 제어할 수 있게 한다.

직접 프롬프팅 대비 다양성을 2~3배 향상시키고 사전 학습 단계의 풍부한 표현력을 복원한다는 효과는 창의적 글쓰기, 콘텐츠 생성, 시나리오 분석처럼 다양성이 핵심 가치인 작업에서 특히 의미 있다. 동시에 안전성이나 정확성을 희생하지 않고 다양성을 확보할 수 있다는 점에서, 기존의 temperature 조정 방식이 갖는 트레이드오프를 우회하는 실용적인 대안이 된다.

다만 모델이 출력하는 점수의 불확실성, 토큰 비용 증가, 후보 간 유사성 문제 등의 한계를 인식하고, 다양성이 실제로 필요한 작업에 선택적으로 적용하는 것이 중요하다. Chain-of-Thought, Role-Based Prompting, Negative Prompting과 결합하면 각 기법의 강점을 살리면서 약점을 보완하는 더 정교한 출력 제어가 가능하다.
