# Chain-of-Thought Prompting Usecase

---

## 개요

Chain-of-Thought Prompting(CoT)은 LLM이 최종 답변을 생성하기 전에 문제를 단계별로 분해하고 중간 추론 과정을 명시적으로 서술하도록 유도하는 프롬프트 설계 전략이다. 본 문서는 실제 CoT Prompting을 적용한 유즈케이스를 기록한다.

LLM은 복잡한 문제에서 최종 답변을 즉시 생성하려 하면 중간 계산이나 논리적 검토 없이 패턴 매칭에 의존하는 추론을 하게 된다. CoT는 중간 추론 단계를 강제함으로써 계산 자원을 재배분하고, Self-Correction 기회를 만들어 출력 품질을 높인다.

> **핵심 공식:** CoT = 문제 제시 + 중간 추론 단계 유도 + 최종 답변 도출

- **모델:** gemini-3-flash-preview

## 문제점

별도의 추론 유도 없이 작업을 요청하면 모델이 형식, 분량, 구조를 스스로 판단한다. 과장 표현, 요청하지 않은 내용 추가, 분량 과도 등의 문제가 발생하며 추론 과정이 불투명하다.

### 주제

블로그 콘텐츠 아웃라인 자동 생성

### 유형

3단계 비교를 통해 추론 유도 방식에 따라 출력 품질이 어떻게 달라지는지 확인한다.

Negative Prompting 키워드로 블로그 콘텐츠 아웃라인 구조를 정리해줘.

Negative Prompting은 LLM에게 하지 말아야 할 것을

구체적인 부정 제약을 사용하는 것이

유형:
- 내용 기반: 특정 주제나 정보 차단
- 형식 기반: 출력 구조/레이아웃 제어

```

## 3단계 비교

### 1단계 — 기본 실행

추론 유도 없이 기본 시스템 프롬프트만 적용한 경우다.

**System**

```
당신은 유능한 어시스턴트입니다.
```

**결과**

```
제공해주신 참고 문서를 바탕으로, 'Negative Prompting(부정 프롬프팅)'을 주제로 한 블로그 콘텐츠 아웃라인을 정리해 드립니다.

# [블로그 아웃라인] AI의 결과물을 200% 개선하는 기술: Negative Prompting 완벽 가이드

## 1. 도입부 (Introduction)
- 공감대 형성: "원하는 답을 얻기 위해 프롬프트를 열심히 썼는데, 왜 자꾸 엉뚱한 내용이 포함될까?"
- 개념 정의: Negative Prompting이란 LLM에게 '하지 말아야 할 것'을 명시적으로 지시하여 출력 품질을 제어하는 기법.
- 핵심 메시지: 긍정 지시(Do)만으로는 부족하다. 정교한 부정 제약(Don't)이 모델을 의도한 방향으로 이끄는 '핸들' 역할을 한다.

...

#프롬프트엔지니어링 #NegativePrompting #LLM #ChatGPT활용법 #AI글쓰기
```

추론 과정 없이 즉시 아웃라인을 생성했다. "200% 개선", "완벽 가이드" 등 과장 표현이 자동 생성되었고 Before & After 사례, 블로그 작성 팁 등 요청하지 않은 내용까지 포함되어 6개 섹션으로 분량이 과도하게 늘어났다. 해시태그도 자동 추가되었다.

### 2단계 — Zero-Shot CoT

시스템 프롬프트에 추론 트리거와 출력 형식 분리를 적용한 경우다.

**System**

```
당신은 유능한 어시스턴트입니다.
- 답변을 작성하기 전에 단계별로 추론 과정을 먼저 생각하세요.
- 추론 과정은 [분석] 레이블 아래 작성하고, 최종 답변은 [결론] 레이블로 시작하세요.
```

**결과**

```
[분석]

1. 주제 분석
제공된 참고 문서를 바탕으로 'Negative Prompting(부정 프롬프팅)'의 개념, 필요성,
4가지 주요 유형을 체계적으로 정리하여 블로그 포스트 아웃라인을 구성해야 합니다.

2. 타겟 독자 설정
LLM(대규모 언어 모델) 활용 능력을 높이고 싶은 일반 사용자 및
프롬프트 엔지니어링에 관심 있는 독자를 대상으로 합니다.

3. 구성 전략
- 도입부: Negative Prompting의 정의와 왜 '하지 말아야 할 것'을 말하는 것이 중요한지 흥미를 유발합니다.
- 본론 1: 긍정 지시문의 한계와 부정 지시문의 효과를 비교 설명합니다.
- 본론 2: 참고 문서에 제시된 4가지 유형(내용, 형식, 말투, 구조)을 상세히 풀어서 설명하고 실무 예시를 제공합니다.
- 본론 3: 효과적인 Negative Prompting 작성 팁을 제안합니다.
- 결론: 요약 및 기대 효과를 제시하며 마무리합니다.

# 블로그 콘텐츠 아웃라인: "AI의 오답을 막는 기술, Negative Prompting 완벽 가이드"

## 1. 서론: 왜 AI에게 '하지 마'라고 말해야 할까?
- 프롬프트의 역설: 원하는 것만 말해서는 원하는 결과를 얻기 힘들다.
- Negative Prompting 정의: LLM에게 특정 요소나 행동을 배제하도록 명시적으로 지시하는 기법.
- 핵심 가치: 출력 품질의 정밀 제어 및 불필요한 정보(노이즈) 제거.

## 2. 본론 1: 긍정 지시 vs 부정 지시, 무엇이 다른가?
- 긍정 지시의 한계: 모델이 창의성을 발휘하다 의도치 않은 방향으로 '할루시네이션(환각)'을 일으키는 경우.
- 부정 지시의 효과: 경계선을 명확히 설정하여 모델의 추론 범위를 좁히고 정확도를 높임.
- 비유: "빨간색으로 그려줘"보다 "파란색과 노란색은 절대 쓰지 말고 그려줘"가 더 강력한 제약이 되는 이유.

## 3. 본론 2: Negative Prompting의 4가지 핵심 유형 및 사례

### ① 내용 기반 (Content-based): 정보의 필터링
- 설명: 특정 주제, 민감한 정보, 경쟁사 언급 등을 차단.
- 예시: "답변에서 정치적인 이슈나 특정 브랜드 이름은 언급하지 마세요."

### ② 형식 기반 (Format-based): 레이아웃의 통제
- 설명: 출력되는 구조나 특정 마크업 언어 사용을 제한.
- 예시: "표(Table) 형식을 사용하지 말고, 불렛 포인트로만 작성하세요."

### ③ 말투/스타일 기반 (Tone/Style-based): 페르소나 유지
- 설명: 원치 않는 어휘, 문체, 전문 용어 사용을 억제.
- 예시: "지나치게 격식 있는 표현이나 어려운 전문 용어는 사용하지 마세요."

### ④ 구조적 기반 (Structural-based): 사고 과정 제어
- 설명: 모델의 추론 방식이나 특정 행동 패턴을 제한.
- 예시: "중간 단계 생략 없이 설명하되, 결론부터 말하는 방식은 지양하세요."

## 4. 본론 3: 효과적인 부정 프롬프트 작성을 위한 꿀팁
- 구체성 확보: "대충 하지 마" 대신 "5문장 이하로 요약하지 마"처럼 수치나 명확한 기준 제시.
- 긍정-부정 조합: "A 방식으로 작성하되(긍정), B 요소는 제외해줘(부정)" 식의 샌드위치 전략.
- 우선순위 설정: 가장 중요한 제약 사항은 프롬프트의 마지막에 배치하여 강조.

## 5. 결론: 더 정교한 AI 활용을 위한 필수 전략
- Negative Prompting은 단순한 거절이 아닌 '정교한 조각' 과정.
- 4가지 유형을 적재적소에 활용하여 업무 효율과 결과물 퀄리티 극대화.
- 마무리 문구: 이제 AI에게 무엇을 '할지'만큼 무엇을 '안 할지'를 알려주세요.
```

[분석] → [결론] 레이블로 추론 과정과 결론이 분리되었다. 추론 단계에서 독자 궁금증을 3가지로 파악하고, 섹션 배치 근거가 생겼다. 과장 표현이 사라지고 아웃라인 구성이 1단계보다 논리적이다. 그러나 파싱은 여전히 불가능하다.

### 3단계 — Structured CoT

추론 경로를 구체적으로 명시하고 검증 단계를 포함한 경우다.

**System**

```
당신은 유능한 어시스턴트입니다.
- 답변을 바로 작성하지 말고, 아래 순서로 먼저 분석한 후 작성하세요.

[분석]
1. 핵심 개념과 팩트를 파악하세요.
2. 독자가 가장 궁금해할 것이 무엇인지 파악하세요.
3. 서론 · 본문 · 결론 각 파트에 배치할 내용을 결정하세요.
4. 논리적 비약이나 누락된 내용이 없는지 검토하세요.

단, 결론을 먼저 정한 후 분석을 끼워 맞추지 마세요.
각 단계의 결과가 반드시 이전 단계의 결과로부터 도출되어야 합니다.

[결론]
위 분석을 바탕으로 답변을 작성하세요.
```

**결과**

```
[분석]

1. 핵심 개념과 팩트 파악
- 정의: LLM에게 특정 행동이나 내용을 '하지 말 것'을 명시하여 출력의 품질을 높이는 기법.
- 핵심 원리: 긍정 지시(Do)의 한계를 보완하고, 모델의 출력 범위를 제한하여 의도한 결과값에 수렴하게 함.
- 4대 유형: 내용 기반(정보 차단), 형식 기반(구조 제어), 말투/스타일 기반(문체 억제), 구조적 기반(행동 패턴 제어).

2. 독자가 가장 궁금해할 것이 무엇인지 파악
- 필요성: "그냥 잘 써달라고 하면 되지, 왜 굳이 하지 말라는 말을 넣어야 하는가?"
- 실전 적용: "각 유형별로 실제 프롬프트에 어떻게 적어야 효과적인가?"
- 차별점: "일반 프롬프트와 Negative Prompting을 섞었을 때 결과가 어떻게 달라지는가?"

3. 서론 · 본문 · 결론 각 파트에 배치할 내용을 결정
- 서론: AI의 답변이 산으로 가는 이유와 Negative Prompting의 개념 소개.
- 본문:
  - 섹션 1: Negative Prompting이 필요한 이유 (긍정 지시의 한계).
  - 섹션 2: 4가지 유형별 상세 설명 및 실전 예시 (참고 문서 내용 구체화).
  - 섹션 3: 효과를 극대화하는 작성 팁 (구체성, 대안 제시 등).
- 결론: 정교한 제어가 만드는 고품질 결과물의 가치 강조.

4. 논리적 비약이나 누락된 내용이 없는지 검토
- 단순히 '하지 마라'는 지시만 있을 경우 모델이 무엇을 해야 할지 몰라 방황할 수 있으므로,
  '부정 지시 + 긍정 지시'의 조합이 중요하다는 점을 본문에 추가하여 논리적 완결성을 높임.

[결론]

# 블로그 콘텐츠 아웃라인: "AI의 답변 품질을 결정짓는 한 끗, Negative Prompting 활용법"

## 1. 서론: 왜 AI는 시키지 않은 일을 할까?
- 문제 제기: 열심히 프롬프트를 짰는데, 사족이 길거나 원치 않는 말투로 답변하는 AI.

- 긍정 지시의 한계: "간결하게 써줘"라고 해도 AI 기준의 간결함은 사용자와 다를 수 있음.
- 노이즈 제거: 불필요한 서론과 결론의 상투적인 문구 차단.

## 적용 효과

| 항목              | 1단계 (기본 실행) | 2단계 (Zero-Shot CoT) | 3단계 (Structured CoT) |
| --------------- | ----------- | ------------------- | -------------------- |
| 추론 과정 투명성       | X           | O                   | O                    |
| 논리적 구조          | X           | 보통                  | O                    |
| Self-Correction | X           | X                   | O                    |
| 과장 표현           | 많음          | 보통                  | 없음                   |
| 분량 통제           | X           | X                   | X                    |
| 파싱 가능 여부        | X           | X                   | X                    |

## 핵심 결과

추론 유도 없이 요청했을 때 모델은 형식과 분량을 스스로 판단하여 과장 표현, 불필요한 내용, 해시태그까지 자동 생성했다.

Zero-Shot CoT("답변을 작성하기 전에 단계별로 추론 과정을 먼저 생각하세요.") 한 문장만 추가하자 [분석] → [결론] 구조로 추론 과정이 분리되고 아웃라인의 논리적 완성도가 향상되었다.

Structured CoT에서 구체적인 추론 경로와 검증 단계를 명시하자 Self-Correction이 발현되었다. 검증 단계에서 "부정+긍정 지시 조합"이라는 누락 내용을 스스로 발견하고 보완한 것이 대표적인 사례다.

> 추론 유도 없을 때: 모델이 즉각적으로 답변 생성 → 패턴 매칭에 의존 → 품질 불안정
> 
> Zero-Shot CoT: 추론 회로 활성화 → 논리적 구조 향상 → 과장 표현 감소
> 
> Structured CoT: 단계별 추론 + Self-Correction → 가장 높은 논리적 완성도

## CoT 원칙

- **추론 트리거** — "단계별로 생각하세요."보다 "답변을 작성하기 전에 단계별로 추론 과정을 먼저 생각하세요"처럼 구체적인 지침이 더 효과적이다
- **출력 형식 분리** — [분석] / [결론] 레이블로 추론 과정과 최종 답변을 명확히 구분해야 파이프라인에서 활용하기 쉽다
- **추론 경로 명시** — 구체적인 순서를 지정할수록 추론의 형식과 깊이를 더 정밀하게 제어할 수 있다
- **검증 단계 포함** — 마지막 단계에 "논리적 비약이나 누락된 내용이 없는지 검토하세요"를 추가하면 Self-Correction이 발현된다
- **부정 지시 결합** — "결론을 먼저 정한 후 분석을 끼워 맞추지 마세요"처럼 추론 오류 패턴을 명시적으로 금지하면 추론 품질이 높아진다
- **파싱 한계** — CoT는 추론 품질을 높이지만 출력 형식은 통제하지 못한다. 구조화된 출력이 필요한 경우 JSON Prompting과 결합해야 한다
